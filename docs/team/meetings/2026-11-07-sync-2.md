| S2-D6 | **VM baseline (A-01):**<br>• Standard_D8s_v5 with Trusted Launch: 128 GB Premium SSD OS disk, 256 GB P15 encrypted data disk.<br>• Windows 11 if the CTO's licence allows (E3/E5, M365 E3/E5 or Business Premium). | S2-D7 | **Drive layout and deny rules:**<br>• `D:\OneDrive`; `D:\FPC\data`, `D:\FPC\backup`, `D:\FPC\exports`. No photo data on C:.<br>• The VM template denies `//d/**` and `//D/**` for Read, Edit, Write, Glob and Grep, plus the OneDrive client folder, the Explorer thumbnail cache and `%LOCALAPPDATA%\FamilyPhotoCurator*` on C:.<br>• The app refuses to start on the VM without `--data`.<br>• Each rule is proven with a canary file.<br>• The **committed** `.claude/settings.json` stays path-based (plus Edit/Write/Glob/Grep for those paths) and doesn't deny `.png` globally, so synthetic UI screenshots stay reviewable in development. |
| S2-D8 | **A-09:** long-lived `multiprocessing.Process` workers, each with its own pipe. The parent kills a worker after its deadline plus 5 s grace and respawns it. An "attempt started" row is written before dispatch; two strikes means quarantine. |
| S2-D9 | **A-10:** the P3 ICC profile is built in code from the published primaries, with pinned constants and a test. Conversion uses relative colorimetric with black-point compensation. HEIC-embedded ICC and `nclx` data is parsed only inside the decoder subprocess. Verified on synthetic patches to ΔE00 < 1. |
| S2-D10 | **Detectors and ranking (A-05 to A-07):** the Data Scientist's priors are adopted as starting configuration. They are uncalibrated and versioned:<br>• **Blink:** above 0.5 counts as closed; 0.35–0.5 gets a soft penalty; faces too small to judge get no penalty.<br>• **Head pose:** yaw 25°/45°, pitch 20°/35°.<br>• **Detection:** EfficientDet-Lite2 at 0.3 with a 2×2 tiled pass; YOLOX-S on standby.<br>• **Background people:** the α/β/γ heuristic.<br>• **Weights:** eyes 0.30, sharpness 0.20, background 0.20, facing 0.15, exposure 0.10, clutter 0.05.<br>• **Early warning, Mon 11-16:** pass lines are 80% small-face recall, 9/10 blink fixtures and 70% small-person recall. Missing two of the three triggers YOLOX or A-23.<br>• **Sanity check:** if R1 flags more than 30% of faces as blinking, the threshold is wrong. |
| S2-D11 | **Testing without weights:** CI uses stubbed detector outputs. Real-model tests carry the `models` marker and run on the VM on synthetic images only, with each run logged. The QE's A-11 canaries and A-21 gate are adopted, with Security's additions:<br>• canaries in XMP, MakerNotes and the ICC description<br>• output file names must be opaque<br>• logs and crash dumps are scanned<br>• no Thumbs.db or desktop.ini on the USB.<br>Agents see only pass/fail counts. |
| S2-D12 | **Model hashes:** the second, confirming download is done from the **CTO's own PC**, a different network path, by Fri 11-13. Security confirms MediaPipe never fetches models by itself. |
| S2-D13 | **Merges:** the Tech Lead cuts `release/holiday-2026` from `main` on Mon by 10:00 and merges gate-green PRs into it. The VM pulls only Tech-Lead tags. The CTO merges to `main` at three points: Wed 11-11 (optional; AGENTS.md and manifests), the Fri 11-20 go/no-go, and after the final export. |
| S2-D14 | **Track B during Track A:** QE pauses B-06, B-08, B-10 and B-14 until Dec 1, and pulls forward only the canaries and background-person scenes from B-04. |
